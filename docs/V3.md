# Version 3: Accuracy

v3 is a **394M-parameter** model focused on being **accurate when it answers and honest when it
doesn't**. It's built in three phases:

| Phase | What | Status |
|---|---|---|
| **1. Groundwork** | Settings, pilot runs, gradient checkpointing, data pipeline with code | ✅ Built and tested |
| **2. Accuracy data** | Wikipedia lookup index (RAG), a teacher model (Qwen2.5-7B-Instruct) that writes practice examples, and chat lessons for every mistake found testing v2 | ✅ Built and tested (steps below) |
| **3. Preference training** | DPO: learn to prefer accurate, honest answers (a teacher model picks the better of two answers) | After v3's chat model exists |

## v2 vs v3

| | v2 | v3 |
|---|---|---|
| Parameters | 88M | **394M** (4.5×) |
| Shape | 768 wide × 12 layers | 1024 wide × 32 layers |
| Memory (context) | 1,024 tokens | **2,048 tokens** |
| Vocabulary | 16,384 | **32,768** (better for code and varied text) |
| Reading | 2.6B tokens (~30 per parameter) | **~11.8B tokens** (~30 per parameter, 45,000 steps) |
| Mix | 80% web, 15% Wikipedia, 5% stories | 63% web, **20% Wikipedia**, **10% Python code**, **5% math**, 2% stories |
| Training time (RTX 4070) | ~17.5–18 hours (measured) | **~13–14 days running 24/7** (pilot: ~25 s/step with `torch.compile`; ~30–38 s/step without) |
| Electricity | ~$1 | ~$20 |
| Disk for data | ~6GB | ~24GB |
| Phone file | ~94MB (Q8) | ~420MB (Q8) or **~240MB (Q4)** |

All v3 layer sizes are multiples of 256, so the smaller **Q4_K** phone format works.

## Step by step (after v2 is finished)

```powershell
cd ~\Projects\a.i-sml
.venv\Scripts\activate
git pull
```

**0. Optional extras (one time):**
```powershell
pip install tensorboard        # live training graphs
pip install triton-windows     # lets torch.compile speed up training on Windows
```
Both are optional: training works without them.

**1. Trial download (~10–15 minutes):**
```powershell
python prepare_web_data.py --version v3 --test
```
Checks that all sources download, including code, math and the top-rated web pages, and that the
test sets (HellaSwag, GSM8K) download for decontamination. It should end with `all done!`.

**2. The real data (several hours):**
```powershell
python prepare_web_data.py --version v3
```
Resumable like v2's: if it stops, run it again. New in v3:
- **Decontamination:** any document containing a public test question is skipped, so test scores
  stay fair. The counts are printed, e.g. `fineweb: done (... 312 documents skipped (test questions))`.
- **The anneal set:** after the main data, it builds `data\v3\anneal\train.bin` (~1.3B tokens of
  top-rated web pages, Wikipedia and math) for the last 10% of training.
- **Reserved special tokens:** the tokenizer includes tokens for lookups (`<|notes|>`), tools
  (`<|tool_call|>`), system prompts (`<|system|>`) and 20 spares, so it never has to change later.

**3. Pilot run (~15–30 minutes):**
```powershell
python train.py --version v3 --pilot
```
It trains ~60 steps into a separate folder and prints a report:
```
speed:          ... s/iter = ...k tokens/s
GPU memory:     ... GB peak of 12.0 GB
loss:           10.4 -> ... (should be going down)
full run:       45,000 iters ~ ... hours (... days)
```
- **`torch.compile: on` or `off`** is printed first. On is 10–30% faster. If it says off, the
  run works fine without it, and a `reason:` line says why. To try to turn it on:
  1. `python -c "import torch; print(torch.__version__)"`, then `pip install -U triton-windows`
     (if pip picks a version that doesn't match your PyTorch, send me the torch version).
  2. Run the pilot again. If the reason mentions a compiler, `cl.exe` or Visual Studio, install
     **Visual Studio Build Tools** (workload: *Desktop development with C++*, several GB), open the
     **x64 Native Tools Command Prompt for VS**, `cd` to the project, activate the venv and rerun.
  - **`FileNotFoundError ... triton ... .json`** means Windows' 260-character path limit. `train.py` now
    puts the compile cache in a short folder (`C:\ti`) by itself. On an older copy, run
    `$env:TORCHINDUCTOR_CACHE_DIR = "C:\ti"` before the pilot.
  3. It counts as working only if the report says `compile=on` **and** `s/iter` is clearly lower
     than before, with a similar loss. If it takes more than an hour, skip it: the run is fine without.
  The first steps are slow while it compiles.
- **Out of memory?** In `config.py` (v3), set `grad_checkpoint=True` and pilot again.
- **Loss not going down?** Stop and send a screenshot.

**Before you start the real run (checklist):**
- **Disk space:** about **20 GB free** on the drive with `checkpoints\`. `latest.pt` is ~4.4 GB, and
  saving it briefly needs room for the old and new copies. `ckpt.pt`, `final.pt` and `pre_decay.pt`
  add ~1.5 GB, ~1.5 GB and ~4.4 GB. Use `--backup_dir` for a daily safety copy of `latest.pt`: a folder on another drive if you have
  one (best, it also protects against a drive failure), otherwise a folder on C: such as `C:\ai-backups`.
  A wrong folder now stops the run in seconds with a clear message, and a backup that fails later only
  prints a warning instead of stopping the training.
- **Windows:** Settings → System → Power → **Sleep: Never**, and Windows Update → **Pause updates**
  (for 5 weeks). If a restart happens anyway, run the same command and it resumes (at most the last
  100 steps are redone).
- **Pilot result:** `full run` should say about **13–15 days** with `torch.compile: on` (about 18–20 without it). If it says much more (say 25+ days),
  send it to me before starting, because the number of steps is decided at the start.
- **GPU:** close games and heavy programs. Check `nvidia-smi` for temperature after the first hour
  (v2 ran at 62–64°C).
- **Wikipedia index:** building it in a second window is fine. It's mostly a single core, so it barely
  slows training.

**4. The real run (~13–14 days, pausable):**
```powershell
python run_training.py --version v3 --backup_dir D:\ai-backups
```
`run_training.py` runs `train.py` and **restarts it automatically after a crash** (an out-of-memory
error, a driver hiccup...), resuming from `latest.pt`, so a crash costs at most ~50 minutes. It
gives up, and says why, after 3 failures in a row that saved nothing. What happened is written to
`checkpoints\dev\v3\supervisor.log`. **Ctrl+C once** pauses safely (it waits for the save, then stops
without restarting); run the same command to resume. Plain `python train.py --version v3` still
works, without the automatic restart. If the PC itself restarts, just run the command again.
Checkpoints go to `checkpoints\dev\v3\`. `--backup_dir` copies `latest.pt` to another drive every 24 hours
(use any folder on a different drive, or leave it out).

What's new while it trains:
- **Mini-exam every 2,000 steps:** `exam 2000: HellaSwag 29.8% (random = 25%)`. It should climb
  slowly, into the 30s. That shows it's really getting smarter, not just lowering the loss.
- **The learning rate stays at 4e-4** for 90% of the run (the "wsd" schedule), then fades over the
  last 4,500 steps while it reads the anneal set. `pre_decay.pt` is saved when the fade starts, so the
  run can be continued later.
- **Graphs:** every number is saved in `checkpoints\dev\v3\metrics.csv`. With tensorboard installed,
  run `tensorboard --logdir checkpoints\dev\v3\tb` in a second window and open http://localhost:6006.

**5. Score it:**
```powershell
python exam.py --version v3          # all 10,042 HellaSwag questions
python exam.py --version v2          # the same test for v2, to compare
```

> **PC needs to be off?** You can rent a GPU and run this same command there: see [CLOUD.md](CLOUD.md).

**Only train at certain hours?** Add a run window, e.g. weeknights and workdays only:
`python run_training.py --version v3 --window 21:00-14:00 --days mon-fri`. It trains inside the window,
saves at the end, waits, and starts again at the next one (leave the window open and the PC awake).
`--days` lists the days a window *starts* on, so mon-fri also runs Friday night into Saturday 14:00.

## Phase 2: lookups and the teacher

The teacher's examples are only needed for chat fine-tuning, so the simplest order is:
**start pretraining as soon as the data and pilot are done**, build the Wikipedia index while it
trains (step A only uses the CPU), and run the teacher (steps B–E, which need the GPU) **after
pretraining finishes**. (It can also run before pretraining, or during a Ctrl+C pause.)
Disk space for everything in v3: about **50 GB**.

**A. The Wikipedia index (several hours, ~10 GB, resumable):**
```powershell
python wiki_index.py build --test                  # 20,000 articles in a few minutes: checks it works
python wiki_index.py build                         # the full index -> data\wiki\wiki.db
python wiki_index.py search "What is the capital of Illinois?"
```
The search should list the Springfield or Illinois article first.

**B. Get the teacher (one time, ~5 GB):**
1. From https://github.com/ggml-org/llama.cpp/releases download the **CUDA** Windows build (the
   `llama-...-bin-win-cuda-...-x64.zip` file) **and** the matching `cudart-...` zip, and unzip both
   into the same folder, e.g. `C:\llama-cuda`. (The CPU build you used for quantizing works, but
   it's far too slow for this.)
2. Download Qwen2.5-7B-Instruct (Apache 2.0 license) as a Q4 GGUF:
   ```powershell
   hf download Qwen/Qwen2.5-7B-Instruct-GGUF --include "qwen2.5-7b-instruct-q4_k_m*.gguf" --local-dir models\qwen
   ```
   (Older installs: `huggingface-cli download` with the same options.) It may arrive in two parts
   (`...-00001-of-00002.gguf` and `...-00002-of-00002.gguf`); always point at the `00001` file.

**C. Start the teacher** in a second PowerShell window and leave it running:
```powershell
C:\llama-cuda\llama-server.exe -m models\qwen\qwen2.5-7b-instruct-q4_k_m-00001-of-00002.gguf -ngl 99 -c 16384 -np 4 --port 8080
```
`-ngl 99` puts it on the GPU, `-np 4` answers 4 requests at once. It's ready when it says
`server is listening`.

**D. Quick check (a minute):**
```powershell
python make_teacher_data.py --task lookup --n 20
python make_teacher_data.py --task instructions --n 20
```
Open `data\v3\teacher\lookup.jsonl` and read a few: a sensible question, a correct answer ending
with `(Source: ...)`, and a wrong answer. Send a screenshot if they look odd.

**E. The real teacher runs (~1–2 days, resumable):**
```powershell
python make_teacher_data.py --task lookup --n 30000
python make_teacher_data.py --task instructions --n 8000
```
It prints how many examples it kept and threw away. Answers that break the rules (no source,
wrong number of list items...) are thrown away automatically, so expect roughly 60–80% to be kept.
If it stops, run the same command again. Close the teacher window when both are done.

## After pretraining: chat lessons, then test

```powershell
python make_chat_data_v3.py                        # builds data\v3\chat.jsonl
python finetune.py --version v3                    # pausable with Ctrl+C
python generate.py --version v3 --chat --lookup    # chat, looking things up first
python evaluate.py --version v3 --lookup           # 41-question test sheet
python evaluate.py --version v3                    # the same without lookups, to compare
python exam.py --version v3                        # HellaSwag
```
`make_chat_data_v3.py` prints how many lessons of each kind it built:

| Kind | Teaches | The v2 mistake it fixes |
|---|---|---|
| lookup | Answer from the notes and name the source | "The capital of Illinois is Paris" |
| dont_know | Notes don't have it → "I don't know" | Confident made-up answers |
| correction | "That's wrong" → recheck the notes and fix it | Repeating "Paris" three times |
| stand_firm | "That's wrong" when it was right → politely keep the answer | (so it doesn't give in to every doubt) |
| memory_doubt | Corrected without notes → admit it's unsure | Guessing again and again |
| instruction | Exact counts and formats | 10 items for "List 3 fruits" |
| topic_switch | Always answer the newest question | Stuck on Illinois when asked about planets |
| unknowable | Personal, live or made-up questions → honest answer | Inventing answers |
| identity | A different answer for each "about you" question | The same paragraph every time |
| small_talk | Casual greetings ("whats up", "how are you", "thanks") | "Whats up" made it invent its own question |

In correction lessons the wrong answer is shown but **not learned** (see `chat.py`): the model only
learns the corrected reply. The v3 test sheet (`eval/prompts_v3.jsonl`, 41 tests) has the original 20
questions plus these mistakes, so v2 can take it too for a fair comparison:
`python evaluate.py --version v2 --prompts eval/prompts_v3.jsonl`.

**On the phone:** lookups need our own app (v4), since PocketPal can't search the index. Without
lookups, v3 still benefits from the bigger brain, the "I don't know" and correction lessons, exact
instructions and topic switching.

## What to expect compared to v2

- **Better facts from memory:** more room to store them, and 3× more reading
- **Longer conversations and documents:** 2,048-token memory
- **Basic Python autocomplete** from the 10% code
- **With the phase 2 lookups:** much more accurate answers, with sources
- **With "I don't know" training:** fewer confident wrong answers
- **Still:** weak at math and multi-step reasoning, and it can still be wrong
