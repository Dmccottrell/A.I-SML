# Version 3: Accuracy (groundwork)

v3 is a **394M-parameter** model focused on being **accurate when it answers and honest when it
doesn't**. It's built in three phases:

| Phase | What | Status |
|---|---|---|
| **1. Groundwork** | Settings, pilot runs, gradient checkpointing, data pipeline with code | ✅ Built and tested |
| **2. Accuracy data** | Wikipedia lookup index (RAG), "read the notes then answer" and "I don't know" chat data, written with help from a local teacher model | Next |
| **3. Preference training** | DPO: learn to prefer accurate, honest answers (a teacher model picks the better of two answers) | After v3's chat model exists |

## v2 vs v3

| | v2 | v3 |
|---|---|---|
| Parameters | 88M | **394M** (4.5×) |
| Shape | 768 wide × 12 layers | 1024 wide × 32 layers |
| Memory (context) | 1,024 tokens | **2,048 tokens** |
| Vocabulary | 16,384 | **32,768** (better for code and varied text) |
| Reading | 2.6B tokens (~30 per parameter) | **~11.8B tokens** (~30 per parameter, 45,000 steps) |
| Mix | 80% web, 15% Wikipedia, 5% stories | 63% web, **20% Wikipedia**, **10% Python code**, **5% math**, 2% stories |
| Training time (RTX 4070) | ~20 hours | **~18 days** (~23 with gradient checkpointing) |
| Electricity | ~$1 | ~$20 |
| Disk for data | ~6GB | ~24GB |
| Phone file | ~94MB (Q8) | ~420MB (Q8) or **~240MB (Q4)** |

All v3 layer sizes are multiples of 256, so the smaller **Q4_K** phone format works.

## Step by step (after v2 is finished)

```powershell
cd ~\Projects\a.i-sml
.venv\Scripts\activate
git pull
```

**1. Trial download (~10–15 minutes):**
```powershell
python prepare_web_data.py --version v3 --test
```
Checks that all five sources download, including the new code and math sources. It should end with `all done!`.

**2. The real data (a few hours):**
```powershell
python prepare_web_data.py --version v3
```
Resumable like v2's: if it stops, run it again.

**3. Pilot run (~15–30 minutes):**
```powershell
python train.py --version v3 --pilot
```
It trains ~60 steps into a separate folder and prints a report:
```
speed:          ... s/iter = ...k tokens/s
GPU memory:     ... GB peak of 12.0 GB
loss:           10.4 -> ... (should be going down)
full run:       45,000 iters ~ ... hours (... days)
```
- **Out of memory?** In `config.py` (v3), set `grad_checkpoint=True` and pilot again.
- **Loss not going down?** Stop and send a screenshot.

**4. The real run (~2.5–3 weeks, pausable):**
```powershell
python train.py --version v3
```
Ctrl+C pauses; the same command resumes. Checkpoints go to `checkpoints\dev\v3\`.

Phases 2 and 3 (lookups, "I don't know" and preference training) add their own steps before chat
fine-tuning. They'll be documented here when they're built.

## What to expect compared to v2

- **Better facts from memory:** more room to store them, and 3× more reading
- **Longer conversations and documents:** 2,048-token memory
- **Basic Python autocomplete** from the 10% code
- **With the phase 2 lookups:** much more accurate answers, with sources
- **With "I don't know" training:** fewer confident wrong answers
- **Still:** weak at math and multi-step reasoning, and it can still be wrong
