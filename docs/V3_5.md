# v3.5: step by step (the ~1.12B model)

v3.5 is v3's design on a bigger brain (2048 wide, 24 layers, 1.124B parameters), trained on 40B
tokens. The plan and reasons are in [ROADMAP.md](ROADMAP.md); this file is the order of steps.

**The final plan (Oct 2026):** 24 layers instead of 22 (1.12B instead of 1.04B, still fits the 4070
at home); 40B tokens instead of 30B, with everyday web pages (DCLM) added **on top of** the same ~19B
educational pages, more code and math, textbook-style text, and human-written Q&A in the final phase;
no TinyStories (written by GPT-3.5/4); a 5,000-question HellaSwag check spread over the whole test.

## The reading (40B tokens)
| Source | Tokens | Share | Why |
|---|---|---|---|
| FineWeb-Edu (educational pages) | 19.0B | 47.5% | school knowledge (the same amount as the 30B plan) |
| DCLM (everyday web: how-tos, forums, reviews, news) | 7.0B | 17.5% | everyday common sense; what HellaSwag measures |
| Wikipedia | 4.5B | 11.25% | ~all of English Wikipedia, read once |
| Code (9 languages, The Stack) | 5.0B | 12.5% | the v4 coding helper (+28% vs the 30B plan) |
| Math (FineMath) | 3.0B | 7.5% | word problems, step by step (+33%) |
| Cosmopedia (textbook-style, written by the open Mixtral model) | 1.5B | 3.75% | clear explanations |
| **Final phase (last 10%, ~4B):** the best FineWeb-Edu pages, DCLM, Wikipedia, math, code, Cosmopedia, and **Stack Exchange questions with their best answers** | | | arrives at chat training used to "question -> helpful answer" |

**Test it cheaply first: v3plus vs v3plus-edu** (after v3 reaches step 40,500 and saves `pre_decay.pt`).
Both continue v3 from just before its fade with ~2.5B new tokens (~18 h, ~$9 each on one RTX 5090),
one with 60% DCLM, one with educational pages only. The full HellaSwag test shows what the everyday web
adds. If v3plus wins, v3.5's mix is confirmed (and v3plus is a better v3). Build the data with
`python prepare_web_data.py --version v3plus` (and `v3plus-edu`): it copies v3's tokenizer.

> **Honest status:** the code is written and tested with a tiny model on a CPU, and the data prep
> is tested against the real datasets (20M-token test). **Nothing has been run on a GPU at 1B size
> yet.** The pilot in step 3 is what turns the numbers below from estimates into facts.

## 0. Before you start
- [ ] Run `python muon_test.py` on the PC (~1-2 hours, while the cloud trains v3). If it reports a clear
      saving (20%+), check it once at v3.5's size, then set `optimizer="muon"` for v3.5 in `config.py`:
      the same quality in fewer steps means a shorter, cheaper run (or more reading in the same time).
- [ ] v3 is finished, chat-tuned and scored (so we know what v3.5 must beat). Keep `final.pt` and back it up.
- [ ] Hugging Face login works (`hf auth login`) and you've accepted The Stack's terms.
- [ ] Decide where it trains: your 4070 (free, ~4 months nonstop) or a rented GPU (see step 2).
- [ ] Disk: v3.5's data is ~88 GB when finished, but **~170 GB free is needed while it's built** (the
      pieces are joined into one file at the end). Delete v3's 27 GB of data (`data\v3`) if tight, but only
      after v3plus's data is built (it doesn't need v3's data, only its tokenizer).
- [x] **Muon test: Muon won** (39M test model, 4,000 steps): val loss 3.8088 vs AdamW's 3.9327, and it
      reached AdamW's final loss at ~step 2,670 (~33% fewer steps). Cloud mode now uses Muon.
- [x] **Muon fits the 4070 too.** Plain Muon keeps its memory on the GPU (~4.5 GB at 1.12B), which doesn't fit 12 GB, so
      `muon_cpu` keeps that memory in system RAM (~5 GB) and moves it to the GPU one weight matrix at a time. Same
      maths, and the saved state is interchangeable with `muon`: a run can start at home (`muon_cpu`, v3.5's home
      default) and finish on rented GPUs (`muon`, the cloud default), or the other way round. Run the pilot to see the
      real GPU memory on your card (`python train.py --version v3.5 --pilot`).

## 1. What the settings are (`config.py`, "v3.5")
| Setting | Value | Why |
|---|---|---|
| Model | 2048 wide x 24 layers, 32 heads, 4 key/value heads, 5,632 feed-forward | 1.124B parameters, all sizes multiples of 256 for phone-friendly Q4 files (~700 MB) |
| Steps | 152,600 x 262,144 tokens | ~40B tokens (~36 per parameter); the fade starts at step 137,340 |
| Learning rate | 3e-4 down to 3e-5, 2,000 warm-up steps | bigger model, gentler steps |
| Optimizer | `adamw_cpu` (optimizer memory in system RAM) | a 12 GB card can't hold weights + gradients + optimizer at 1B |
| Gradient checkpointing | on (`checkpoint_every=1`) | same reason; `2` is faster if memory allows |
| Save every | 50 steps | about every 1-1.5 hours at ~70-95 s per step |

**Cloud mode (`--cloud`)** drops those 12 GB workarounds on a big rented GPU (24-32 GB+, e.g. RTX 5090):

| Setting | Home (4070) | Cloud mode (`--cloud`) |
|---|---|---|
| Optimizer | **`muon_cpu`** (Muon, memory in RAM) | **`muon`** (Muon, memory on the GPU): the same optimizer, so one run can move between home and cloud mode |
| Gradient checkpointing | on | off (~30% faster) |
| Micro-batch | 1 x 2048, 128 per step | 2 x 2048, 64 per step (same ~262k tokens per step) |
| Save every | 50 steps | 150 steps (a checkpoint is ~17 GB) |

The steps, learning rate and results are the same, so **one run can move between home and cloud mode at
any step** (tested: a checkpoint saved with `adamw_cpu` continues with `adamw` and back, identically).
`cloud_setup.sh` and `handoff.py up --start` use it automatically. If a cloud pilot runs out of GPU
memory, add `--set grad_checkpoint=true` to the pilot and the run (`--set` changes any one setting).

## 2. Where to train: estimates (scaled from v3's measured 6.9 s/step on an RTX 5090; 1.12B, 40B tokens)
| Where | Time | Cost |
|---|---|---|
| Your RTX 4070, nonstop | ~5-6.5 months | ~$160-390 electricity |
| 1x RTX 5090, cloud mode | ~36-46 days (longer than a 29-day listing allows) | ~$360-580 |
| **2x RTX 5090, cloud mode** | **~20-25 days** | **~$420-530** (at ~$0.87/hr) |
| 4x RTX 5090, cloud mode | ~10-13 days | ~$510-650 |
| 1x H100 | ~2-2.5 weeks | ~$650-1,000 |
If Muon passes its test, take ~20-30% off the rented times and costs.

Rented prices swing a lot; check them on the day. Time on your PC only counts the hours it runs
(see the 24/7 table in ROADMAP.md). The pilot gives real seconds per step, and then these become
firm. The RTX 5090 needs a newer PyTorch (2.7+, CUDA 12.8): check it before renting one.

## 3. Pilot (10 minutes, on the machine that will train)
```
python train.py --version v3.5 --pilot                       (home: the RTX 4070)
torchrun --standalone --nproc_per_node=2 train.py --version v3.5 --cloud --pilot   (2 rented GPUs)
```
Look at the PILOT REPORT:
- **GPU memory** must stay under the card's size (12 GB on the 4070). If it runs out, in `config.py`
  keep `checkpoint_every=1`; if it still runs out, tell me (the fallbacks are `optimizer="adamw8bit"`
  or a slightly smaller model).
- **Speed:** expect ~75-105 s per step on the 4070. Multiply by 152,600 for the real time.
- **Loss** should fall from ~10.4 (about ln 32768) to ~8-9 within 60 steps.
- **RAM:** with `adamw_cpu` you need ~17 GB free RAM. Close other programs and check Task Manager.
If `checkpoint_every=2` fits in memory and is faster, use it.

## 4. Build the data (~88 GB, ~170 GB free while building; ~5-8 hours)
Build it on the machine that will train (a home upload of 66 GB is too slow).
```
python prepare_web_data.py --version v3.5 --test      # 20M tokens: checks logins and dataset names (minutes)
python prepare_web_data.py --version v3.5             # the real thing; resumable, run it again if it stops
```
It downloads and encodes 40B tokens + a 4.1B "best material" set, and trains a new 32k tokenizer that
has seen every code language (if `data\v3.5\tokenizer.json` already exists it's kept: copy the SAME
tokenizer to every machine that builds v3.5 data, so home and cloud data match). Test questions are removed. **Note:** a restart re-reads what it did
before (needs the internet again), so avoid stopping it late in the run. Check the speed first
with `python bench_source.py fineweb_100bt --version v3.5`.

## 5. The real run
```
python run_training.py --version v3.5 --backup_dir C:\ai-backups
```
Same behaviour as v3: restarts after a crash, Ctrl+C once to pause, `--window` for set hours,
`handoff.py` to move it between your PC and a rented machine (see CLOUD.md). What to watch:
- HellaSwag mini-exam every 5,000 steps on **5,000 questions** (`exam_questions`; v3's used 500), so each
  score is steady to about ±0.7 points instead of ±2. Logged as `hellaswag_5000`; compare it with v3's
  full-test score (`exam.py`), not its 500-question mini-exams. v3.5 should clearly beat v3.
- Validation loss falling; at step 137,340 the learning rate starts to fade on the "best material" set.
- Back up `latest.pt` (~9 GB for v3.5: weights 4.5 GB + Muon's memory ~4.5 GB).

### Start at home, finish on 2x RTX 5090
v3.5's home default is `muon_cpu` and the cloud default is `muon`: the same Muon, so a run can start on the 4070 and
move to the rented GPUs with nothing lost (train.py refuses to mix Muon with AdamW, with a clear message).
1. On the PC: data (step 4), the pilot (step 3: check the GPU memory it reports), then
   `python run_training.py --version v3.5 --backup_dir C:\ai-backups`. At ~90-105 s/step the 4070 does ~900 steps a day
   (~0.6% of the run a day): small progress, but it proves the whole pipeline on real data before money is spent.
2. When v3 is done on the 5090 (and its files are downloaded): rent 2x RTX 5090, then on the PC:
   Ctrl+C once in the training window (pause), wait for "saved", and
   `python handoff.py up --host root@<ip> --port <port> --cloud_gpus 2 --start` (uploads latest.pt, ~9 GB: about
   1 hour at 2.5 MB/s, and starts it there in cloud mode). The rented machine builds its own data
   with `cloud_setup.sh v3.5` first; copy `data\v3.5\tokenizer.json` to it so both use the same tokenizer.
3. The PC is then free for v3's chat training, DPO and the v3plus comparison.

## 6. After pretraining
1. `python exam.py --version v3.5` and compare with v3.
2. Chat lessons: `python make_chat_data_v3.py --version v3.5` builds everything v3 learned (lookups,
   "I don't know", corrections, memory, reply suggestions) into `data/v3.5/chat.jsonl`, reusing v3's
   teacher examples; then `finetune.py --version v3.5`. It must beat v3 on the same tests before it
   replaces it: `python compare.py --old v3 --new v3.5` (see "Every version builds on the last" in ROADMAP.md).
3. Evaluate with and without lookups (`evaluate.py --version v3.5 --lookup`).
4. Export and quantize to Q4 (~650 MB) for the phone, and Q8 (~1.1 GB) for the PC.

## What can go wrong
| Problem | What to do |
|---|---|
| Out of GPU memory | Section 3: checkpointing on, then `adamw8bit`, then tell me |
| Out of RAM (`adamw_cpu`) | Close programs; you need ~17 GB free; or train on a 24 GB rented GPU |
| `The Stack` access error in prep | Accept the terms on its Hugging Face page, `hf auth login` again |
| Loss goes to `nan` or jumps up | Stop; send me the last 100 lines (I'd lower the learning rate and resume from an earlier save) |
| Too slow for you | Rent GPU time for the pilot-verified plan (CLOUD.md) |
