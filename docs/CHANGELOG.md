# Changelog

What changed, newest first. Measured numbers live in [BENCHMARKS.md](BENCHMARKS.md); each model's details are in [VERSIONS.md](VERSIONS.md).

## October 2026 (late)

### Latest
- **Feature flags:** Settings > Owner > **Features and testing** (owner and admins) controls who sees each new feature: Off, Owner, Admins, Testers or Everyone. New features start with the owner and admins, you widen the audience when you are happy, and Off rolls a feature back at once. A list of named testers can be added. Changes apply immediately and are written to the security log. See [FEATURE_FLAGS.md](FEATURE_FLAGS.md).
- **Welcome tour (the first flag):** an animated introduction and walk-through the first time someone signs in: the model family, answers with sources, making it yours, VryxCode, and for admins the owner tools. Swipe, tap Next or use the arrow keys; Skip any time. Replay it from Settings > About or the account menu. It is on for the owner and admins until you choose Everyone.
- **Message box lower on iPhones:** the box now sits about 34pt closer to the bottom of the screen (the home indicator is only a thin line, so the full safe area was wasted space) and the usage line under it is tighter. For Safari and the iPhone installed app only, the app also fills the real screen height instead of the browser's "dynamic viewport" height, which can come out shorter in the installed app and leave an empty band under the message box. Android and desktop are not affected.
- **iPhone installed app (PWA) fixed:** the app drew under the notch and status bar and under the home bar, so the top buttons and bottom controls were partly hidden: the header, side panel, coding screen, settings, sign-in and dialogs now keep clear of both. The chat search box had 15px text, and iPhones zoom the whole page in when a text box smaller than 16px is tapped (and do not zoom back), which made everything look too big: every text box is now 16px on touch screens. Checked in Chromium with an iPhone-size screen and simulated notch (59px) and home bar (34px).
- **Sign out is easy to reach:** an icon at the top right of the side panel (one tap after opening it), and **Sign out** in the account menu at the bottom. It asks once, then signs this device out.
- **Who Emvryx says it is:** when someone asks who or what it is ("who are you", "who made you", "what's your name", "introduce yourself"), the app answers in the owner's words for every model: **"I am Emvryx, created by Darryl McCottrell."** No model call and no web search. A direct question about what it is built on ("are you ChatGPT / Qwen?", "what model are you?") adds one true sentence: "I'm built on an open foundation model." Change the wording in `app/identity_answer.py`.
- **Safer auto-start script:** `windows\install_autostart.ps1` now refuses a llama-server path that does not exist (or is the `C:\path\to\...` example), and keeps the previous start file as `start_emvryx.cmd.bak`. Running it again rewrites the start file, so it needs the same options as before (`-Port`, the real `-Llama`, `-CodeSandbox`); the old example values had put the app on port 8000 while the tunnel expected 8001, which showed as "Bad gateway".
- **Faster, safer start-up:** the check that Docker is ready for VryxCode's sandbox now runs in the background. Before, the app waited for it before it started listening: with Docker Desktop slow to wake after a restart the app took 20 seconds or more to answer, and chat.emvryx.app showed Cloudflare's "Bad gateway" meanwhile. The log says "Checking Docker for VryxCode in the background..." and reports the result when it has it.
- **VryxCode for admins:** an admin the owner appointed can now use VryxCode (and the Cloud machine) like the owner, whatever their plan and without the Docker sandbox. Ordinary people still need VryxCode in their plan and the Docker sandbox turned on (start the app with `--code-sandbox docker` while Docker Desktop is running): VryxCode runs programs on the Emvryx PC, so letting strangers use it without a container would be unsafe.
- **Seconds counter in regular chats, and the coding screen's thinking line fixed:** while a model is thinking in a normal chat, the line now shows how long it has been (12s, then 1m 05s). On the coding screen the line ("Mulling it over... 30s") no longer blanks and fades back in each time the page asks the server for news (the line is moved, not rebuilt), the seconds no longer step backwards when the server's whole-second count is a second behind, and the numbers use a fixed width so the line doesn't jiggle.
- **GitHub import, two fixes:** the repository picker now says when your connection can only see public repositories (private ones missing) and how to fix it (a classic token with the repo permission, or a fine-grained token on All repositories with Contents: read and write), shows how many it found, and has a box to import any repository by name. Copying a repository from a Windows PC no longer starts git with an empty environment: git keeps what it needs to reach the internet (SystemRoot, proxy and certificate settings), retries with the Windows certificate store when a certificate check fails, and a failure now says in plain words what went wrong (certificate, no route to github.com, token not accepted, repository not found) with git's own text kept underneath.
- **Admins can delete accounts:** Settings > Owner > People now has a **Delete...** button on each person. It asks you to confirm it is you (password and two-step code, if you have them) and to type the person's name, then removes the account and everything it owned (chats, saved notes, memory, coding projects, devices, connected apps, usage). Any admin can delete an ordinary account. Only the PC owner and the owner's email account can delete an admin or no-limits account. The first owner account and your own account can't be deleted here (your own has its own button in Settings > Account). The security log records who did it.
- **Import your GitHub repositories:** VryxCode > project menu > **Import from GitHub...** lists the repositories your connected account can see (search box, private ones marked); tap one to copy it into a new project of its own, still linked to GitHub for pull and push. A failed copy leaves no empty project behind. The same list is behind **Browse my repositories...** in a project's GitHub window.
- **Gmail connect errors explained:** an app password pasted with its spaces now works; the app tells apart "needs an app password", "IMAP is switched off", "sign in through a browser first", "could not reach the mail server" and a plain refusal, each with what to do.
- **The app remembers more:** the "Protect the owner account" bar stays away for two weeks after "Not now" (it came back on every visit because only the visit was remembered), and the app reopens the chat you were in, even if you left it on an empty new chat. Settings pages on a phone have an **X** (next to the back arrow) to close them.
- **More than one owner or admin, with a plan of your choice:** in Settings > Owner > People, the first owner account now has a **Plan and rights...** button on each person: pick Free, Pro or Mega, switch **No usage limits** on or off, and switch **Admin rights** on or off. An admin who is not marked no-limits keeps the normal plan caps. Only two accounts can hand these out: the PC owner, and the account with the owner's own email (darrylmccottrell16@gmail.com, listed as `grant_emails` in `.emvryx/security.json`) once the PC owner has made it an admin; signing up with that email gives no power by itself. Other admins cannot make more admins, and admin accounts cannot be turned off from the People page. From the command line: `python app_server.py --make-admin you@example.com --plan mega --unlimited`.
- **Easier sign-up:** invite codes work however you type them (capitals, spaces, with or without dashes) and the dashes are added for you as you type, in the app and in the website box. A name with a space ("Darryl McCottrell") now works: the space becomes _, and signing in with the space works too.
- **Copies of the last reply are caught:** if a model answers a new message with (nearly) the same text as its previous reply, the app takes the copy back and asks once more, firmly and a little less predictably, with a note quoting what was just asked. The Study helper now writes exactly the number of practice questions you ask for (for example 15) with no answers, instead of one at a time. A request such as "give me 15 questions" is no longer mistaken for the answer to a quick check.
- **Repeating in Study helper fixed:** a short reply such as "30" to "Quick check: What is 6 x 5?" used to look like nothing in particular, so the model repeated its last message. The model is now told, out of sight, that the message is the answer to that exact question and to say whether it is right. Nothing extra is saved in the chat.
- **No more pretend searching:** when you say "look online", "check again" or "google it", the app now really searches the web (it used to depend on the message looking like a question). A follow-up such as "how many goals has he had" is searched together with your earlier question, so "he" has a name. If a model still writes "*Checking online*" when no search ran, the app runs the real search and the model answers again. Private chats never search, even then.
- **The first message after a restart is no longer 100 seconds late:** a model now counts as loaded only after one tiny request has gone through it (health said ready before the weights were really in memory), and at start-up the app loads the model you used last in the background (`last_model.json` in the data folder). Measured on the owner's PC: first reply `model_first_word=101 s`, every later one under 1 s.
- **Slow first answers explained:** at start-up the app now prints a "Speed:" line when the models would run on the processor instead of the graphics card (a CPU build of llama-server, or no `-ngl` option), and logs any model load longer than 15 seconds. Only one model is kept in memory, so switching models (for example Apogee then Equinox) reloads it. `--timings` shows load, first word and total for every reply.
- **Cleaner website menu:** every page now has one menu. Desktop shows Models, Plans, How usage works, About and a **More** menu (What's new, Scorecard, What's next) beside the Open Emvryx button. On a phone it is a single row with the button and a menu (hamburger) button that opens a tidy list. The page you are on is marked. Fixed the What's next heading showing a raw code.

- **Calmer chat, and a real test for the sources:** under each answer only Copy, Right, Regenerate (and Continue when needed) stay visible; Save as, Ask a stronger model, Branch and Report moved behind one **...** button. In Settings > Owner > Live sources and keys (and the Live sources dialog), **Test them now** really asks Tavily, Brave, Gemini, Wikipedia and seven main data sources one tiny question each and shows a tick or a cross with the reason. ### Lessons learned
- Hugging Face private storage counts about 15 minutes late after deletes: upload small adapters and the 4-bit file, not the 29 GB merged model.
- Conversion needs free disk; `llama-quantize` must be built on a fresh cloud machine.
- Plain the newer open bases bases score near zero on some of our sheets because of the hidden `<think>` block, so those gaps are not quoted as gains.
