# Changelog

What changed, newest first. Measured numbers live in [BENCHMARKS.md](BENCHMARKS.md); each model's details are in [VERSIONS.md](VERSIONS.md).

## October 2026 (late)

### Latest
- **VryxCode keeps going after a bad step (Oct 20):** when a reply ran out of room in the middle of a file, the whole file was thrown away and asked for again, so it was cut off at the same place three times and the run stopped. Now the whole lines it wrote are saved and the model is asked for the rest from that line on (with the last lines shown so it knows where it is). After 3 unreadable steps the model is shown a plainer way to send them and keeps working; a run stops only after 6 in a row. Unreadable replies are kept short in its memory so it does not copy them. 5 new tests.
- **VryxCode lasts much longer on your plan (Oct 20):** every step sends the whole project again, and each step was counted as if all of it were new text, so a Mega tank ran out after a handful of Apogee 3 steps (and paused with 15% still showing). Steps now count at a fifth of a chat message of the same size (limits.json `code_rate`), the text the last step already sent is counted as cached, and "about N coding steps" is worked out from a real step on that model. A Mega tank now lasts dozens of Apogee 3 steps. 4 new tests.
- **VryxCode reads Apogee 3's steps (Oct 20):** Apogee 3 was stopped as "garbled" three times in a row. VryxCode now also reads tool calls written the way the Emvryx 3 models' base writes them (`<function=write_file><parameter=path>...`), where a file's quotes and line breaks need no escaping, and Balanced/Quick give a step 8,192 tokens (was 4,096) so a whole page fits. The stop message no longer tells you to pick Apogee when you are on Apogee. 3 new tests.
- **Stop really stops (Oct 20):** Stop pressed while a model is still loading ends the load ("Stopped before the answer started."), and if the page is still waiting 6 seconds after Stop it stops waiting by itself, keeping what was written. 1 new test.
- **No second search when the model asks you something (Oct 20):** "I don't know which city you live in. Please tell me..." counted as "I don't know", so the app searched the web and answered all over again while the finished answer sat on screen. A question back to the person no longer starts a search.
- **Less waiting for models (Oct 20):** Apogee 3 is always loaded at its VryxCode window (128K), so going from chat to VryxCode and back never reloads it; opening VryxCode starts loading Apogee 3 straight away, so the first task does not wait for it. 1 new test.
- **VryxCode on Apogee 3 at 128K (Oct 20):** VryxCode gave every model 32K; a model can now have its own VryxCode window (models.json `code_context`), and Apogee 3 codes at 128K with 8-bit chat memory (chat stays at 80K). With effort-only VryxCode (the default for the owner and admins) Apogee 3 is the only model it uses once it is on the computer. 2 new tests.
- **Apogee 3's scores, and Equinox 3 at 256K (Oct 19):** Apogee 3's What's new and tour now show its measured results: HellaSwag 75.4% (plain grown base 74.5%; just ahead of Solstice 3), thinking test 83.6% on Deep and 95.7% answering straight away, identity 16/16, long memory 3/3 at 32K, 64K and 128K. Equinox 3 goes to 256K like Flare 3 and Solstice 3 (8-bit chat memory, about 6.4 GB on the RTX 4070; it was tested to 128K, so `scripts/long_check.py --model equinox-3 --kv8 --sizes 196608,262144` confirms the rest).
- **A speed line under each reply, for the owner and admins (Oct 19):** "⏱ 9.8s in all · looking it up 1.2s · loading the model 0s · first word at 6.1s · thought first (Deep) · answered twice", so a slow reply shows where its time went. The house rules also stop "the provided search results" talk and ask for a plain "that has not happened yet" plus what is known.
- **Looked-up questions answer fast on Deep (Oct 19):** with web or Wikipedia notes (or live facts) the answer is in the notes, so an Emvryx 3 model answers from them straight away instead of thinking at length first; and when a model says it does not know and the app searches, the second answer no longer thinks all over again. Deep still thinks for questions with no notes. 2 new tests.
- **Deep answers sooner, and a reply you switch away from keeps its question (Oct 19):** on Deep an Emvryx 3 model could think for a minute and a half about a simple question on the RTX 4070, and even run out of room before answering. Its hidden thinking is now capped (40% of the reply's room, at most 1,600 tokens): at the cap the thinking is closed and the model answers from what it worked out. Switching away from the page while it worked dropped the live connection; the page then showed the chat as saved on the server, which (while the model was still loading) did not have the question yet, so it disappeared, and the seconds started again from zero. Now the question stays on screen and the clock carries on. 2 new tests.
- **House rules for Emvryx 3 in chat (Oct 19):** until the 3.x models are retrained on Lessons 4, every chat message to them carries a short note only the model reads: answer exactly what was asked, never claim what the person did not say, no flattery, no emoji unless they use them, at most one "!", remembered facts and other people only when they help, commands and links written out, and say so when unsure. Behind the `chat_house_rules` flag (owner and admins first). 3 new tests.
- **Memory stays on topic, and Lessons 4 holds the voice (Oct 19):** a message about the person ("I need to download it") used to bring everything remembered about them, so Equinox 3 worked a friend's name into an unrelated answer. Now only the remembered facts that share a word with the message go with it (and their name); asking about themselves ("what do you remember about me", "my friend...") still brings everything. The lesson factory now fails drafts that open with filler or flattery ("You're awesome", "congrats") or stack up "!" or emoji, so they are rewritten instead of kept. 2 new tests.

### Lessons learned
- Hugging Face private storage counts about 15 minutes late after deletes: upload small adapters and the 4-bit file, not the 29 GB merged model.
- Conversion needs free disk; `llama-quantize` must be built on a fresh cloud machine.
- Plain the newer open bases bases score near zero on some of our sheets because of the hidden `<think>` block, so those gaps are not quoted as gains.
